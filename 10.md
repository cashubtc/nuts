# NUT-10: Spending conditions

`optional`

`used in: NUT-28`

---

The `secret` is a public key, which authorizes the spend and can commit to further conditions. A proof on a [pre-v3 keyset](02.md#keyset-id-v3) follows [legacy NUT-10](legacy/10.md).

## Nutroot secrets (v3 keysets)

`Proof.secret` is a compressed secp256k1 public key, bare for a proof without spending conditions ([NUT-00](00.md#secret-bytes)).

A proof with spending conditions commits them into the key, following [BIP341](https://github.com/bitcoin/bips/blob/master/bip-0341.mediawiki)'s construction with Cashu tags. The secret is the tweaked key:

```
secret = P = K + t*G,  where  t = tagged_hash("Cashu_NutrootTweak", K || merkle_root)
```

`K` is the **internal key** (33-byte compressed) and `merkle_root` commits to a tree of [condition leaves](#condition-leaves). `tagged_hash` is [NUT-00](00.md#tagged-hashes)'s. The tweak `t` is reduced mod the curve order `n`.

A secret has two spend paths, as in BIP341: the **key path**, a signature by the secret's own scalar ([NUT-00](00.md#key-path)), and the **script path**, which reveals one leaf of the tree with its merkle path and satisfies that leaf ([below](#script-path)).

A key-path spend reveals only a signature on `P`. A script-path spend reveals `K`, the exercised leaf and its keys.

### The internal key

`K` takes one of three forms:

- A **single-party** key: its holder can key-path spend, and without conditions it is the secret, untweaked.
- An **aggregated** key (MuSig2, FROST: nobody holds its scalar) **MUST** carry at least the empty tweak `t = tagged_hash("Cashu_NutrootTweak", K)`, no merkle root bytes.
- A **NUMS offset** key makes the secret **script-only** (unspendable via key path): BIP341's NUMS point `H` offset by a fresh random scalar.

  ```
  H = 0250929b74c1a04954b78b4b6035e97a5e078a5a0f28ec96d547bfee9ace803ac0
  K = H + u*G          u: a fresh 32-byte random scalar per proof
  ```

  `H` **MUST** be `lift_x(SHA256(G_uncompressed))`: SHA-256 over G's **65-byte uncompressed** SEC1 encoding, taken as an x-coordinate.

  `u` **MUST** be fresh per proof and **MUST** be disclosed in [spend info](#spend-info); holders verify `K - u*G == H`. Seeded wallets derive it per [NUT-13][13] type `0x02`.

### Condition leaves

```
leaf = leaf_version (1 byte) || leaf_type (1 byte) || field TLVs
```

The field TLVs are a [NUT-00](00.md#tlv-encoding) field stream, and that exact byte string is the leaf everywhere: in spend info, in a witness, and as the hash preimage. Leaf version `0x00` is defined here; other versions are reserved and, when a mint evaluates a spend, **MUST** be treated as unsatisfiable.

The field vocabulary of version `0x00` (allocated types are even; odd types are reserved):

| Field   | Type   | Value                                                                  |
| ------- | ------ | ---------------------------------------------------------------------- |
| `n`     | `0x02` | signature threshold, 1 byte                                            |
| `keys`  | `0x04` | concatenated 33-byte compressed public keys, one record                |
| `time`  | `0x06` | unix seconds, minimal big-endian, at most `2^53 - 1`                   |
| `hash`  | `0x08` | SHA-256 digest, 32 bytes                                               |
| `dests` | `0x0c` | concatenated 33-byte compressed public keys, one record ([NUT-YY][YY]) |

- An unknown field, odd ones included, **MUST** be rejected.
- A known field on the wrong leaf type is malformed and **MUST** be rejected.

The core leaf types, each optional ([Signaling](#signaling)):

| Leaf        | Type   | Fields (all required) | Satisfied by                                                            |
| ----------- | ------ | --------------------- | ----------------------------------------------------------------------- |
| `threshold` | `0x01` | `n`, `keys`           | signatures by `n` distinct listed keys                                  |
| `after`     | `0x02` | `n`, `keys`, `time`   | verifier's clock >= `time`, plus signatures by `n` distinct listed keys |
| `hashlock`  | `0x03` | `n`, `keys`, `hash`   | preimage of `hash`, plus signatures by `n` distinct listed keys         |
| `commit`    | `0x04` | `hash`                | no witness: it binds the tree to 32 bytes of outside context            |

#### Optional leaves

Other NUTs define further leaf types and fields, each listed in these tables with a link to its NUT; an allocated number keeps its meaning. A mint implements an optional leaf only when it lists it in [`leaves`](#signaling); elsewhere it is unsatisfiable, as an unknown type.

| Leaf       | Type   | Fields               | Defined in   |
| ---------- | ------ | -------------------- | ------------ |
| `template` | `0x05` | `n`, `keys`, `dests` | [NUT-YY][YY] |

Leaf types `0x06` to `0xfe` are unallocated, and `0xff` is never allocated. When a mint evaluates a spend, a leaf type it does not [list](#signaling) **MUST** be treated as unsatisfiable, disabling only that path of that proof.

Leaf validation:

- `n` **MUST** be at least 1 and at most the number of listed keys.
- `keys` **MUST** list at least one valid compressed secp256k1 point; two keys sharing an x-coordinate are one signer counted twice and **MUST** be rejected.
- A leaf body (the bytes after `leaf_version`) **MUST NOT** exceed 512 bytes, so a serialized leaf is at most 513 bytes.
- A `commit` leaf carries `hash` and no other field. A witness revealing it **MUST** be rejected.

Multisig is a `threshold` leaf; a refund is an `after` leaf naming the refund keys; an HTLC is a `hashlock` leaf. Combinations are multiple leaves in one tree. A `commit` leaf's `hash` is defined by the protocol relying on it.

Every spendable leaf type names at least one key.

### The tree

```
leaf_hash = tagged_hash("Cashu_NutrootLeaf", serialized_leaf)
branch    = tagged_hash("Cashu_NutrootBranch", min(h1, h2) || max(h1, h2))
```

The merkle root of a single leaf is its leaf hash. For more leaves, the fold is normative: sort the leaf hashes ascending (lexicographic byte order) once, then pair per level in that order, an unpaired last hash promoted to the next level unchanged, until one hash remains.

Duplicate leaves are permitted; the fold **MUST NOT** deduplicate. See the [test vectors][tests] for a worked fold, including the promoted odd leaf and a duplicate pair.

A merkle path is the list of sibling hashes from the leaf to the root. A tree of more than 8 leaves **MUST** be rejected, so a path has at most 3 sibling hashes.

### Spend info

The fields of [NUT-00 spend info](00.md#spend-info) follow these rules:

- `k` is mutually exclusive with `E` and with `u`: a proof **MUST NOT** carry `k` alongside either.
- `K` **MUST** be present when a tree is disclosed with neither `k` nor `E`, and **SHOULD** accompany `E` so third-party leaf signers can build the control block.
- `tree`, when present, **MUST** hold at least one leaf: an empty array is malformed.
- `u` **MUST** be present when the internal key is a [NUMS offset](#the-internal-key) and **MUST NOT** be present otherwise. `u` without a `tree` or without `K` is malformed.
- A key derived from `E` **MUST NOT** be sent on as a bearer `k`: sweep, then send.

> [!CAUTION]
>
> A key derived from `E` is the receiver's static private key offset by a value its sender knows ([NUT-28][28]). If it is sent on as a bearer `k` and reaches that sender, they learn the static key. The forwarded proof looks like any other bearer proof, so only the forwarder can prevent this.

#### Receive-time verification

These rules extend [NUT-00's receive-time verification](00.md#receive-time-verification) for spend info that its check 1 sends here, and every rule there applies here.

A receiver **MUST** reject spend info that carries any of: `k` alongside `E` or `u`; an empty `tree`; `u` without a `tree` or without `K`.

**Check 1: The spend info reconstructs the secret.**

The spend info conveys the **internal key**, the key the secret is built from, by the first of these routes that applies:

1. **bearer**: `k*G` from `k`;
2. **NUMS**: `H + u*G` from `u`; `E`, when present, blinds leaf keys only ([NUT-28][28] slots `1..`);
3. **receiver-keyed**: the key the wallet derives from `E` ([NUT-28][28] slot `0`), when `K` is absent or equals it;
4. **disclosed**: `K` itself; `E`, when present, blinds leaf keys only ([NUT-28][28] slots `1..`).

On routes 1 and 2, a disclosed `K` that differs from the internal key **MUST** reject.

By spend-info shape:

- No `tree`:
  - routes 1 and 3: the internal key or its [empty tweak](#the-internal-key) **MUST** equal the secret.
  - route 4: the internal key's [empty tweak](#the-internal-key) **MUST** equal the secret.
- A disclosed `tree`:
  - every leaf **MUST** parse (an unknown version, type, or constraint field rejects: the wallet cannot evaluate it), and a `commit` leaf adds no spend path.
  - the internal key tweaked by the recomputed root **MUST** equal the secret.
- Anything else, including a tree without a key source: reject.

Leaves may be transmitted in any order: a permuted `tree` reconstructs the same root and **MUST** be treated as equivalent.

**Check 2: The wallet can spend it.**

As well as the keys NUT-00 counts, the wallet holds a spend path when it holds:

- the key path, by a key derived from `E`, the scalar of a disclosed `K`, or a cosigner share of an aggregated `K`; or
- keys satisfying a disclosed leaf of a type the mint [lists](#signaling).

An [optional leaf](#optional-leaves) counts only at a mint that lists it, and only as its NUT allows.

Every spendable disclosed leaf is a spend path open to its signers (eg a refund after `time`), which the wallet **MUST** evaluate under its acceptance policy ([NUT-00](00.md#receive-time-verification)).

### Script path

```json
{
  "leaf": "<serialized leaf, hex>",
  "control": { "K": "<33-byte hex>", "path": ["<32-byte hex>", ...] },
  "signatures": ["<128-char hex>", ...],
  "preimage": "<hex>" // hashlock leaves only
}
```

Script-path signatures sign the **script digest**, which binds the [input digest](00.md#the-transaction-transcript) to the revealed leaf:

```
script_digest = tagged_hash("Cashu_NutrootScript", input_digest || leaf_hash)
```

The presence of `leaf` selects script-path verification. The verifier **MUST**:

1. Reject a `path` containing more than 3 sibling hashes.
2. Recompute `leaf_hash -> root` through `path`, then the tweak from `K` and the root, and check that `K + t*G` equals the secret; otherwise reject.
3. Parse the leaf, failing closed on any unknown version, type, or field.
4. Evaluate the leaf: for `after`, check its local clock is at or past `time`; for `hashlock`, check `SHA256(preimage) == hash`, with the preimage exactly 32 bytes; for an optional leaf, its NUT's condition; then count the distinct listed keys with a valid BIP-340 signature over the script digest and require at least `n`.

Thresholds count distinct satisfied keys. A witness is invalid if `signatures` holds more entries than the leaf lists keys, if any entry is not 64 bytes, or if `preimage` is present on a leaf other than `hashlock`. Mints **MAY** reject a serialized witness longer than 4096 characters; every valid witness fits when compactly encoded.

### Signaling

Leaf types are optional. A mint **MUST** list the leaf types it understands in its [NUT-06][06] setting; a mint that lists none, or has no setting, accepts [key-path](00.md#key-path) witnesses only:

```json
{
  "10": {
    "supported": true,
    "leaves": ["0001", "0002", "0003", "0004"]
  }
}
```

Each entry is `leaf_version || leaf_type` as lowercase hex, in any order. A wallet **MUST** only build a lock from leaf types the mint lists. `supported` keeps its [legacy meaning](legacy/10.md#mint-info-setting).
