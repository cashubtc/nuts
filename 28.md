# NUT-28: Pay-to-Blinded-Key (P2BK)

`optional`

`depends on: NUT-10`

---

## Summary

This NUT describes Pay-to-Blinded-Key (P2BK), which blinds the keys inside [NUT-10 nutroot secrets](10.md#nutroot-secrets-v3-keysets).

P2BK preserves privacy by blinding each receiver pubkey `P` with an ECDH-derived scalar `rᵢ`. Both sides can deterministically derive the same `rᵢ` from their own keys, but a third party cannot. This improves user privacy by preventing the mint from linking multiple spends by the same party.

## ECDH Shared Secret (Zx)

Elliptic-curve Diffie–Hellman (ECDH) allows two parties to create an x-coordinate shared secret (`Zx`) by combining their private key with the public key of the other party: `Zx = x(epG) = x(eP) = x(pE)`.

For P2BK, the sender creates an ephemeral keypair (private key: `e`, public key: `E`), which protects the privacy of their usual long-lived public key. They then calculate the shared secret by combining the ephemeral private key (`e`) and the receiver's long-lived public key (`P`).

The receiver calculates the same shared secret `Zx` using their private key (`p`) and the ephemeral public key (`E`), which is supplied by the sender in the proof's [spend info](00.md#spend-info).

The shared secret `Zx` is then used to derive the blinded public keys.

## Deriving Blinded Public Keys

Each enumerated key is permanently blinded using a deterministic blinding scalar (`rᵢ`), where `i` is its _slot index_ in the [slot map](#nutroot-secrets-v3-keysets).

The blinding scalar for each slot is calculated as:

```
rᵢ = SHA-256( DOMAIN_SEPARATOR || Zx || i_byte)
```

Where:

- `DOMAIN_SEPARATOR` constant byte string `b"Cashu_P2BK_v1"`
- `Zx` is the ECDH shared secret (`eP` for sender, `pE` for receiver).
- `i_byte` is the single unsigned byte representation of `i`
- `||` denotes concatenation

If `rᵢ` is not in the range `1 ≤ rᵢ ≤ n−1`, retry once with an extra `0xff` byte appended to the hash input as follows:

```
rᵢ = SHA-256( b"Cashu_P2BK_v1" || Zx || i_byte || 0xff )
```

If `rᵢ` is still not in the range `1 ≤ rᵢ ≤ n−1`, abort and discard the ephemeral keypair.

Finally, the public key (`P`) for slot `i` is blinded (`P'`) as follows:

```
P' = P + rᵢG
```

### Example

Below is an example implementation in TypeScript.

```ts
function deriveP2BKBlindingTweakFromECDH(
  point: WeierstrassPoint<bigint>, // E or P
  scalar: bigint, // p or e
  slotIndex: number, // i
): bigint {
  // Calculate x-only ECDH shared point (Zx)
  const Zx = point.multiply(scalar).toBytes(true).slice(1);
  // One index byte: refuse values outside 0-255.
  if (!Number.isInteger(slotIndex) || slotIndex < 0 || slotIndex > 255) {
    throw new Error("P2BK: slot index out of range");
  }
  const iByte = new Uint8Array([slotIndex]);
  // Derive deterministic blinding factor (r):
  // Note: bytesToNumber does NOT reduce modulo n
  let r: bigint = bytesToNumber(sha256(Bytes.concat(P2BK_DST, Zx, iByte)));
  if (r === 0n || r >= secp256k1.Point.CURVE().n) {
    // Very unlikely to get here!
    r = bytesToNumber(
      sha256(Bytes.concat(P2BK_DST, Zx, iByte, new Uint8Array([0xff]))),
    );
    if (r === 0n || r >= secp256k1.Point.CURVE().n) {
      // Astronomically unlikely to get here!
      throw new Error("P2BK: tweak derivation failed");
    }
  }
  return r;
}
```

For detailed examples of slot blinding, see the [test vectors][tests].

> [!IMPORTANT]
> All receiver keys **MUST** be in compressed SEC1 format (33 bytes) before ECDH and blinding. \
> The sender **MUST add an '02' prefix** to BIP-340 x-only pubkeys (eg Nostr).

## Deriving Private Keys

With P2BK, the public locking keys are permanently blinded. The mint sees only the blinded public keys, and expects signatures from the corresponding private key.

The receiver must therefore derive the correct blinded private key (`k`). Because BIP-340 lifts public keys to even-Y parity, there are two possible derivation paths:

- Standard derivation: `k = (p + rᵢ) mod n`
- Negated derivation: `k = (-p + rᵢ) mod n`

Where `p` is the receiver's long lived private key.

To decide which derivation to use, the receiver calculates their natural pubkey (`pG`) and compares the parity to their actual pubkey (`P`).

If the parity matches, use standard derivation, otherwise use negated derivation.

The fastest way to do this in a wallet is to unblind, verify the key is a match, then select derivation by parity:

a. compute `Rᵢ = rᵢG` \
b. unblind `P = P' − Rᵢ` \
c. verify `x(P) == x(pG)` \
d. use standard derivation if `parity(P) == parity(pG)`, otherwise use negated derivation

## Nutroot secrets (v3 keysets)

The derivation above applies to the keys inside [NUT-10 nutroot secrets](10.md#nutroot-secrets-v3-keysets) as follows:

- **The slot map.** Slot `0` is always the internal key `K`, which for a bare output is the secret itself. Slots `1..` are the entries of `keys` fields, walking the spend-info tree list in transmitted order, keys within each leaf in order.
- **Slot `0` is always blinded**, except a [NUMS](10.md#the-internal-key) internal key, which takes its per-proof uniqueness from the offset `u`. Slot indices are unchanged either way.
- **Receivers match by value** ([NUT-00](00.md#receive-time-verification)): derive the candidate key for each slot in `1..N` (`N` = number of enumerated keys) and take whichever slot reproduces a key in the tree.
- **At most 256 enumerated slots per secret**, exactly the one index byte: slot `0` plus at most 255 leaf keys. An index that does not fit the byte **MUST** be refused.
- **One fresh ephemeral per output**, including receiver-keyed quote locks ([NUT-04](04.md#nutroot-transactions-v3-keysets)). A NUMS output with no blind-me keys carries no ephemeral ([NUT-18](18.md#nutroot-locking-v3-keysets)).
- **Whether a leaf key is blinded is its owner's choice**, carried on the key's delivery channel (eg a payment request's `b` set, [NUT-18](18.md#nutroot-locking-v3-keysets)). Slots count every enumerated key either way.
- **The ephemeral travels in spend info**: `E` is [spend info field](00.md#spend-info).

See the [test vectors][tests] for a worked slot derivation and value match.
